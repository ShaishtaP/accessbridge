# Deployment

AccessBridge runs on free tiers: three Render services defined in [`render.yaml`](../render.yaml), MongoDB Atlas for data, and the audit worker on a local machine.

| Part | Where | URL |
|---|---|---|
| React client | Render static site `accessbridge-app-sp` | https://accessbridge-app-sp.onrender.com |
| Express API | Render free web service `accessbridge-api-sp` (Singapore) | https://accessbridge-api-sp.onrender.com/api/health |
| Demo site (seeded defects) | Render static site `accessbridge-demo-sp` | https://accessbridge-demo-sp.onrender.com |
| Database | MongoDB Atlas M0 (Mumbai) | – |
| Audit worker | Local machine (`npm run start:live`) or Docker | – |

## Why the worker is not hosted

The worker drives headless Chromium through Playwright, which needs roughly 1 GB of memory. Free web-service tiers offer 512 MB, so the worker runs where memory is available. Because the job queue lives in MongoDB, a worker anywhere with database access picks up jobs queued through the deployed API: no extra networking is required.

## Configuration

| Variable | Service | Value |
|---|---|---|
| `MONGODB_URI` | API | Atlas connection string, entered in the Render dashboard (`sync: false`) |
| `JWT_SECRET` | API | Generated by Render (`generateValue: true`) |
| `CORS_ORIGIN` | API | The client's origin; browsers on other origins are refused |
| `AUDIT_ALLOWLIST` | API, worker | The deployed demo site, replacing the localhost demo used in development |
| `VITE_API_URL` | Client (build time) | The API's public URL; empty in development, where Vite proxies `/api` |
| `NODE_VERSION` | API, client | `22` |

Pages on other public sites can be audited once a workspace registers the site and proves ownership (meta tag or `/.well-known/accessbridge.txt`); every request, redirect and DNS answer still goes through the SSRF guard.

## First deployment

1. Render → **New → Blueprint** → select the `accessbridge` repository. Render reads `render.yaml` and lists the three services.
2. Enter `MONGODB_URI` when prompted, then **Apply**. The first build takes a few minutes per service.
3. Atlas → **Network Access** must allow the API's outbound addresses. Free Render services have no fixed IP, so the access list contains `0.0.0.0/0`; access is still protected by the database user's password.
4. Check `https://accessbridge-api-sp.onrender.com/api/health` reports `"status": "ok"` and `"db": "connected"`.

Every push to `main` redeploys the changed services automatically.

## Running audits against the deployed site

```bash
cd worker
npm run start:live
```

`start:live` loads [`worker/live.vars`](../worker/live.vars) (the production allowlist, no secrets) and reads `MONGODB_URI` from `server/.env`. The Docker image works the same way with `AUDIT_ALLOWLIST` set on the container.

## Free-tier behaviour

- The API sleeps after 15 minutes without traffic; the next request wakes it in about 30–60 seconds.
- Render's disk is ephemeral: uploaded screenshots are lost when the API restarts or redeploys. Issues, notes, timelines and audit results are stored in Atlas and are not affected. Persistent screenshots would need object storage (for example S3 or Cloudflare R2).
- API latency includes the round trip from Singapore to the Atlas cluster in Mumbai.
