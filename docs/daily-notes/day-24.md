# Day 24 — Free deployment on Render

## Done
- `render.yaml` Blueprint with three free services:
  - **accessbridge-api-sp**: Express API as a Node web service in Singapore, health-checked on `/api/health`.
  - **accessbridge-app-sp**: the React client as a static site, with a rewrite to `index.html` for client-side routes.
  - **accessbridge-demo-sp**: the demo site's pages and assets as a static site.
- Client reads the API base URL from `VITE_API_URL` at build time; protected file downloads use the same base.
- API restricts CORS to the origins in `CORS_ORIGIN`; without it (local development) any origin is allowed.
- Production allowlist (`AUDIT_ALLOWLIST`) points at the deployed demo site instead of the localhost demo.
- `npm run start:live` in `worker/` loads `worker/live.vars` (production allowlist, no secrets) so a local worker processes jobs queued through the deployed API.
- Deployment guide in `docs/deployment.md`.

## How
- Secrets stay out of the repository: `MONGODB_URI` is entered in the Render dashboard (`sync: false`) and `JWT_SECRET` is generated by Render.
- The job queue lives in MongoDB, so the worker does not need to be reachable from the internet; it only needs database access. This keeps Chromium off the 512 MB free tier.
- Service names fix the public URLs, which are referenced in `VITE_API_URL`, `CORS_ORIGIN`, `AUDIT_ALLOWLIST` and `live.vars`.

## Result
- https://accessbridge-api-sp.onrender.com/api/health → `200 {"status":"ok","db":"connected"}`.
- https://accessbridge-app-sp.onrender.com serves the client, including deep links such as `/workspaces/:id` (200).
- https://accessbridge-demo-sp.onrender.com serves all four demo pages.
- A CORS preflight from the client origin returns `Access-Control-Allow-Origin: https://accessbridge-app-sp.onrender.com`.
